CSCI 391 — Agentic Artificial Intelligence Lab 1 — Environment Setup & First Chatbot

Lab Overview

This lab establishes the development environment for CSCI 391 and introduces the first implementation of an LLM-powered application. You will first build a bare-bones chatbot using Python and OpenRouter, then extend that application by adding web search with Tavily. The lab is intentionally hands-on: you are expected to implement the missing functionality, run the provided tests, inspect the outputs, and explain what you observe.

The lab also introduces an important distinction from our first lecture: an application that calls an LLM is not automatically an agent. You will evaluate the chatbot against the formal definition of an agentic AI system and then consider how adding an external tool changes the application's capabilities.

Learning Objectives

Upon successful completion of this lab, students will be able to:

  • Configure the Python development environment used for CSCI 391.
  • Use environment variables to securely provide API credentials to a Python application.
  • Implement a basic conversational application using an LLM API.
  • Test an LLM application using repeatable prompts and expected behaviors.
  • Explain why a basic chatbot does not satisfy the formal definition of an agentic AI system.
  • Implement an external web-search capability using the Tavily client library.
  • Evaluate how external information retrieval changes the quality and usefulness of LLM responses.
  • Explain how a system prompt influences an LLM application's behavior and customizability.

Part 2 — Implement the Bare-Bones Chatbot

Save chatbot_starter.py as chatbot.py in your Lab1 folder and complete every TODO. Your finished application should follow this flow:

  1. Load environment variables from your .env file using python-dotenv, then retrieve OPENROUTER_API_KEY via os.environ.get().
  2. Optionally accept a model identifier as a command-line argument so the active model can be switched without editing source code.
  3. Define a system prompt string that sets the assistant's role and behavior.
  4. Read the user's question from standard input.
  5. Send the system prompt and user message to the OpenRouter chat completions endpoint and receive a response.
  6. Print the assistant's reply to the console.
📖 Reference Documentation
  • OpenRouter — Chat Completions API Reference — request body, authentication, and response schema
  • OpenRouter — Quickstart Guide — end-to-end example of a first API call
  • OpenAI — Chat Completions Reference — shared message format (role, content, choices)
💡 Tip Every request requires a messages array containing at minimum a system message and a user message. The response text lives at choices[0].message.content in the returned JSON.

Part 4 — Is This Chatbot an Agent?

In lecture, an Agentic AI System was defined as software that, given a goal expressed in natural language, chooses its own next action from a set of tools, executes that action against an external environment, observes the result, and repeats the cycle until it judges the goal to be met or gives up.

Use this definition to analyze your bare-bones chatbot. Explain where the application falls short. Your response must address all six elements:

  • A goal expressed in natural language.
  • Choosing its own next action.
  • A set of tools.
  • Executing an action against an external environment.
  • Observing the result and repeating the cycle.
  • Continuing until the goal is met or the system gives up.

Your answer should clearly distinguish between an LLM generating text in response to a prompt and an agent taking actions in an environment.

Part 5 — Add Web Search with Tavily

You will now extend the chatbot so that it retrieves current information from the web before asking the LLM to answer. Save chatbot_extended_starter.py as chatbot_extended.py in your Lab1 folder and complete every TODO. Your extended application should follow this flow:

  1. Read the user's query from standard input.
  2. Pass the query to the Tavily search client to retrieve a set of relevant, up-to-date web results.
  3. Combine the search results with the original user query to form an enriched prompt.
  4. Send the enriched prompt to the OpenRouter chat completions endpoint.
  5. Print the model's response to the console.
📖 Reference Documentation
  • Tavily — Python SDK Reference — client initialization, search() method, and result schema
  • Tavily — REST API Reference — request parameters, search depth options, and response fields
  • app.tavily.com — create an account and generate your API key

Setup Steps

  1. Create a Tavily account at app.tavily.com ↗. You may sign up with your GitHub account or university email.
  2. Generate a Tavily API key from the dashboard.
  3. Add the key to your .env file using the variable name TAVILY_API_KEY.
  4. Open chatbot_extended_starter.py (shown on the next page) and complete every TODO.
  5. Run your extended chatbot from the Assignments\Labs directory once all TODOs are implemented.
💡 Tip Review the Tavily result schema carefully. Each result object contains a url, title, and content field. Decide how you will format and inject these fields into your LLM prompt so the model can reason over them effectively.
