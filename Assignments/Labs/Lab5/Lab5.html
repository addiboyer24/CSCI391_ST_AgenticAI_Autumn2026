★ Extra Credit This lab is optional. It takes about an hour, and Lab 6 does not depend on it. Everything runs on your own machine plus a web browser — no Node.js, no API keys, and no deployment.

Prerequisites

Read Chapter 9, "Model Context Protocol," from The Agentic AI Bible by Thomas R. Caldwell. Focus on the three connection phases (initialization, discovery, invocation) and on what MCP standardizes (the envelope) versus what it leaves to you (what each tool means).

Lab Overview

In Labs 2–4 every tool lived inside your agent's script, with schemas you typed by hand. MCP moves tools into a server. Any MCP client connects, asks what the server offers (tools/list), and calls what it needs (tools/call). The client learns the tools at runtime, not when you write the code.

You will build a small Review Toolkit server with Gradio, following the Hugging Face MCP Course, and connect it to the MCPJam web app, an MCP client with a built-in LLM chat. You write no client code.

Learning Objectives

  • Expose Python functions as MCP tools with Gradio's mcp_server=True.
  • Explain how docstrings, type hints, and input components become a tool's JSON Schema.
  • Call MCP tools by hand and through an LLM, and explain how descriptions drive the LLM's choice.

Part 1 — How Gradio Builds an MCP Tool

When you call demo.launch(mcp_server=True), Gradio turns every function behind a gr.Interface into an MCP tool. You never write a JSON Schema — Gradio derives it from your code:

In your codeIn the published tool
Function nameTool name
Docstring summary + Returns:Tool description
Args: entry for a parameterThat property's description
Type hint (str, int)Property type
gr.Radio([...]) inputProperty enum — the Lab 4 pattern, generated for you
Input component value=Property default; the parameter is no longer required

For example, the provided sentiment_analysis function is published as:

{ "name": "sentiment_analysis", "description": "Analyze the sentiment of the given text. Returns: str: A JSON ...", "inputSchema": { "type": "object", "properties": {"text": {"type": "string", "description": "The text to analyze"}}, "required": ["text"] } }
⚠ No Docstring, No Description A function with no docstring is still published — with "description": "" on the tool and on every parameter. Gradio will not warn you. You will see what that does to an LLM in Part 5.

Part 2 — Implement the Server

Create review_toolkit_starter.py in your Lab5 folder from the listing in Part 3. Complete every TODO, then save the finished file as app.py. sentiment_analysis is the tool from the Hugging Face course and is already complete. You add two more:

  1. Statistics (TODO 1). Implement text_statistics: return JSON with word_count, sentence_count, and avg_sentence_length (rounded to one decimal). Use the provided split_words and split_sentences helpers. Write a docstring with a summary line, an Args: block, and a Returns: line.
  2. Ranking (TODO 2). Implement rank_sentences: score each sentence's polarity, sort according to order, and return the first top_k as a JSON list of {"sentence", "polarity"} objects. Its docstring must describe all three parameters — say what each value of order means.
  3. Register (TODO 3). Add one gr.Interface per new tool to the gr.TabbedInterface and give each a tab name. For rank_sentences, use a gr.Radio for order so the schema gets an enum, and gr.Number(precision=0) for top_k so it is an integer.
  4. Launch (TODO 4). Start the MCP server and a public share link: demo.launch(mcp_server=True, share=True).
ℹ Why a Share Link? The MCPJam web app runs in your browser but connects only to HTTPS servers, and your server runs on plain http://127.0.0.1. share=True opens a temporary public https://….gradio.live tunnel to your machine. It lasts about a week and closes when you stop app.py.
💡 Why the Helpers? TextBlob's own .words and .sentences need an extra NLTK download (punkt_tab) that a fresh machine does not have, so the tool would error on every call. The regex helpers avoid it. Sentiment scoring does not need it.

Debugging Tip

When a tool raises an exception, MCP clients see only "The upstream Gradio app has raised an exception but has not enabled verbose error reporting." While developing, add show_error=True to launch() and read the full traceback in the terminal running app.py.

Part 3 — Starter Implementation

review_toolkit_starter.py complete every TODO before running
import json import re import gradio as gr from textblob import TextBlob # --------------------------------------------------------------------------- # Helpers (provided). They avoid TextBlob features that need extra downloads. # --------------------------------------------------------------------------- def split_sentences(text): """Split text into sentences on . ! or ? followed by whitespace.""" return [s.strip() for s in re.split(r"(?<=[.!?])\s+", text.strip()) if s.strip()] def split_words(text): """Return the words in text (letters, digits, and apostrophes).""" return re.findall(r"[A-Za-z0-9']+", text) # --------------------------------------------------------------------------- # Tool 1 (provided): from the Hugging Face MCP Course, Unit 2 # --------------------------------------------------------------------------- def sentiment_analysis(text: str) -> str: """ Analyze the sentiment of the given text. Args: text (str): The text to analyze Returns: str: A JSON string containing polarity, subjectivity, and assessment """ sentiment = TextBlob(text).sentiment result = { "polarity": round(sentiment.polarity, 2), # -1 (negative) to 1 (positive) "subjectivity": round(sentiment.subjectivity, 2), # 0 (objective) to 1 (subjective) "assessment": "positive" if sentiment.polarity > 0 else "negative" if sentiment.polarity < 0 else "neutral", } return json.dumps(result)

Part 4 — Run and Connect

Step A — Run the server

python app.py

Gradio prints a local URL and, after a few seconds, a public one:

* Running on local URL: http://127.0.0.1:7860 * Running on public URL: https://xxxx.gradio.live

Open http://127.0.0.1:7860/gradio_api/mcp/schema and confirm all three tools have descriptions and order has an enum.

Step B — Connect MCPJam

  1. Open app.mcpjam.com in your browser.
  2. Add a server with the HTTP connection type and your public URL plus the MCP path — keep the trailing slash:
    https://xxxx.gradio.live/gradio_api/mcp/
  3. Connect — MCPJam runs initialize and tools/list — then run each tool by hand on this review:
The trail to the summit was absolutely beautiful. Parking was a nightmare. The rangers were friendly and helpful! The bathrooms were disgusting.

Part 5 — Let a Model Choose

Open MCPJam's chat, make sure your server is enabled, and pick one of the free models (some require a free MCPJam sign-in). Send each prompt in a new chat, pasting the Part 4 review for <REVIEW>, and check the trace view for the tool call.

PromptExpected tool call
1. Is this review positive or negative overall? <REVIEW>sentiment_analysis
2. How many sentences and words are in this review? <REVIEW>text_statistics
3. What are the two worst things this reviewer said? <REVIEW>rank_sentences
order=most_negative, top_k=2
4. What is the tallest mountain in Montana?No tool
ℹ A Correct Call Can Still Be a Wrong Answer TextBlob scores "Parking was a nightmare." as 0.0 — its word list has no entry for "nightmare." Note whether the model repeats that score or overrides it. Agents inherit the limits of their tools.

Now Remove the Descriptions

Copy app.py to app_nodoc.py, delete the docstrings from text_statistics and rank_sentences, and rename them tool_a and tool_b (including the matching fn= arguments). Stop app.py, run app_nodoc.py, reconnect MCPJam to its new share URL, and rerun prompts 1–4 with the same model.

💡 Lab Focus Watch the arguments, not just the tool. Without an Args: description, does the model still guess that top_k means "how many"? The enum on order survives, because it comes from gr.Radio, not from the docstring.

C. Final Lab Reflection

Answer the following questions. Keep each response to 2–4 sentences.

1. MCPJam had never seen your server before you connected it, yet it called your tools correctly. Which MCP message made that possible, and what did it return?

2. Using your Section B results, explain why "MCP lets any agent use any tool" is only half true.

3. The order="worst" call never reached your function. Why is it useful that the schema is enforced before your code runs?

Final Thought MCP standardizes the envelope: discovery, invocation, and transport. Whether a model can use your tool still depends on what you put inside — a clear name, an honest description, and a schema that rules out bad input.
